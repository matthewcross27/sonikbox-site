# Project agent memory

This file is the project's committed home for project-intrinsic agent knowledge: build, test, release, architecture, and sharp-edge notes that should travel with the code.

- Static site, no build step: `index.html` + `css/styles.css` + `js/main.js`, no bundler/npm dependency. Open `index.html` directly or serve the directory; there is nothing to `npm install` or compile.
- Visual system is "Rack Panel": brand tokens (`#ff5500` orange / `#08080a` bg / `#111115` panels), `border-radius: 0` everywhere, Archivo Black for headlines, IBM Plex Mono for labels/specs (both Google Fonts, linked in `index.html`'s `<head>`). Keep new UI consistent with the `.rack-panel` (screw-corner), `.led`, and `.vu-meter` utility classes in `css/styles.css` rather than inventing new decoration.
- Three rules carry the page's document character, and new UI has to follow all three or it will read as a different site. Orange is fill and never type: anything that would be orange lettering is white, and the orange returns as a block (the `.module-card-head` plate, the `.hero h1 .accent` highlight, selected `.hub-toggle`/`.addon-option`, the `.summary-total .value` stamp, the `.cta-module` plate). Every field name shares one label treatment, declared as a single grouped rule above `.eyebrow`. Blocks sit flush left, not centred.
- `css/styles.css`'s `:root` holds the whole design system: colour, `--space-*`, `--fs-*`, `--tap`, and the motion curves `--ease-out`/`--ease-in-out`. Size and space new UI from those tokens; a raw px value or a bare `ease`/`linear`/`ease-in` timing function in a rule is drift, not a choice. `.rack-panel` draws its screw heads as four background gradients, so anything that sets the `background` *shorthand* on a panel silently wipes `background-size` and blows them up to full-box washes - set `background-color` instead. Panel content also has to clear the first and last 17px of the box or it sits on a screw. The neutral scale (`--panel`, `--border`, `--border-dim`, `--text-dim`, `--screw`, plus the hardcoded screw-gradient and `.led--idle` greys) deliberately shares one warm ~28deg hue with the brand orange and the `.cta-module` on-orange overrides - don't reintroduce a cooler blue-grey when adding a token to this scale.
- `body` takes its colour from `var(--text-dim)`, which resolves once on `body`; descendants inherit the resulting colour, not the variable. Redefining a colour token on a subtree therefore does nothing to inherited text unless that subtree also re-declares `color`. This bites any themed or inverted section.
- Motion follows one system, all in `css/styles.css` + `js/main.js`. `.reveal` marks a small, deliberate set of section-level blocks (never individual cards) for a one-time scroll entrance; it only ever hides content once `js/main.js` has confirmed `IntersectionObserver` support and no `prefers-reduced-motion`, at which point it adds `.js-reveal` to `<html>` and flips `.is-revealed` per element - without that ancestor class `.reveal` does nothing, so a failed script never leaves content stuck invisible. The `@media print` block forces `.reveal` fully visible regardless of scroll state, since the rider can be printed via keyboard shortcut before `#specs` has ever scrolled into view. The hero's own entrance is a separate, simpler `@keyframes hero-reveal` staggered by `animation-delay` (no JS, no scroll-triggering) since it's above the fold. Reduced motion is handled once, globally: instead of zeroing every transition/animation duration (which would also kill colour/opacity fades), the block overrides `transition-property` to an allowlist of `color, background-color, border-color, opacity` and sets `animation: none`, so movement-bearing properties (`transform`, `clip-path`) snap to their end state while colour and opacity keep fading. Any new pressable needs `transform: none !important` added to that block's explicit list alongside the press-feedback `scale(0.97)` it presumably declares on `:active`. The one mouse-reactive touch (`.hero-photo-frame` 3D tilt) is wired in `js/main.js`, gated on `hover:hover`/`pointer:fine` and reduced motion together, and driven through the `--tilt-x`/`--tilt-y` custom properties declared on that element - not on `.hero-photo-panel`, which already owns the load-time entrance transform and would conflict.
- The gear-spec rows in `#specs` are captain-maintained: correct them to real equipment only on the captain's explicit instruction, and never invent, embellish, or guess a model, generation, or capability claim. Several legacy rows still describe gear the studio may not have; the captain corrects them incrementally, so raise a suspect row as a question rather than editing it unasked.
- `book@sonikbox.studio` is a placeholder inbox, not a live booking system. It's wired into the nav/hero/CTA-band buttons via `mailtoUrl()` in `js/main.js`, and separately hardcoded as a static `mailto:` href in each `.cta-address` fallback text link (hero, CTA band, footer) - update both if the address ever changes. A future task may need to swap this for a real backend/form.
- The `#specs` "Print Studio Rider" button (`js/main.js` `#print-rider-btn`) relies on the `@media print` rules at the bottom of `css/styles.css`, which hide everything except `#specs` and re-theme it black-on-white. The printed rider is its own document: it opens with the `.print-only` title block, hides the on-screen `.section-head-row`, and drops the module grid to one column with a wider label track. If you restructure `#specs`, update those print rules too, and re-check that Module 05's add-on prices still print.
- `assets/img/control-room.jpg` and `assets/img/lounge.jpg` are the two real studio photos (downloaded from the live site, not placeholders) — reused for hero/hub imagery and as the Open Graph/Twitter preview image.
- No real logo asset exists; the "SONIKBOX" wordmark is styled text (`.logo` in `css/styles.css`), not an image/SVG mark.
