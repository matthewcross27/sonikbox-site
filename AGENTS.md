# Project agent memory

This file is the project's committed home for project-intrinsic agent knowledge: build, test, release, architecture, and sharp-edge notes that should travel with the code.

- Static site, no build step: no bundler/npm dependency anywhere. Open a page directly or serve the directory; there is nothing to `npm install` or compile.
- **Two designs are currently live side by side for a client A/B comparison** (added 2026-09, temporary): `index.html` + `css/styles.css` is Design A ("Rack Panel", the long-shipped system, default at the root); `version-b.html` + `css/styles-b.css` is Design B ("Signal & Night", full-bleed/document-style, added for this comparison). Both pages share the same `js/main.js` and `assets/img/*` unmodified - the estimator, nav, reveal, and photo-tilt behavior is identical on both, only the two stylesheets differ. Each page carries a small `.version-switch` badge (top-right, fixed) linking to the other, plus a tiny inline redirect script at the top of `<head>` that honors `?v=a`/`?v=b` and a remembered `localStorage["sonikbox-version"]` choice - `index.html` is the one with the "smart" redirect-away-if-preference-is-b logic; `version-b.html` never redirects away except on an explicit `?v=a`, so a direct link to it is always reliable. **When the captain picks a direction:** delete the loser's HTML/CSS file, delete the `.version-switch` block and inline script from the winner's HTML, delete its `.version-switch` CSS rules and the `.version-switch` line in its `@media print` list, and rename the winner's files back to `index.html`/`css/styles.css` if it was Design B.
- Design A ("Rack Panel", `css/styles.css`): brand tokens (`#ff5500` orange / `#08080a` bg / `#111115` panels), `border-radius: 0` everywhere, Archivo Black for headlines, IBM Plex Mono for labels/specs (both Google Fonts, linked in `index.html`'s `<head>`). Keep new UI consistent with the `.rack-panel` (screw-corner), `.led`, and `.vu-meter` utility classes rather than inventing new decoration. Three rules carry its document character: orange is fill and never type (the `.module-card-head` plate, the `.hero h1 .accent` highlight, selected `.hub-toggle`/`.addon-option`, the `.summary-total .value` stamp, the `.cta-module` plate); every field name shares one label treatment declared above `.eyebrow`; blocks sit flush left, not centred. `.rack-panel` draws its screw heads as four background gradients, so setting the `background` *shorthand* on a panel silently wipes them - set `background-color` instead, and keep panel content clear of the first/last 17px of the box. The neutral scale (`--panel`, `--border`, `--border-dim`, `--text-dim`, `--screw`) deliberately shares the brand orange's warm ~28deg hue - don't reintroduce a cooler blue-grey there.
- Design B ("Signal & Night", `css/styles-b.css`): full-bleed photography, a continuous document-style gear rider instead of a card grid, and one full-orange finale section instead of repeated plates. Typefaces are **Archivo Black (display, headlines only) and IBM Plex Mono (everything else)** - the same pairing as Design A, on the captain's explicit instruction to match Design A's fonts exactly; an earlier draft used Fraunces for display, so if you see that name anywhere it's stale. Orange is fill, never type here too, reimplemented as a handful of deliberate moments rather than a repeated plate: the `.hero-fill` highlighter behind the hero's second headline line, the `.logo-word .mark` nameplate chip ("BOX"), the small `.module-mark` patch-light square before each gear module heading, and the `.finale` section, which is the *only* place the whole page goes fully orange. Breakpoints are 700px (label-track/two-column gear rows), 860px (nav switches from hamburger to inline links; hero, hubs, and the estimator switch to their two-column layouts), and 1200px (hero copy gets extra side padding) - 390/820 land below 860, 1024/1440 land above it. `.module-row-stacked` (Module 05's synth/drum/DJ rows) goes full-width rather than sharing the narrow label column with plain rows, on screen and in print alike - a long label plus a status tag doesn't fit the 30ch track otherwise.
- Both stylesheets' `:root` holds their whole design system: colour, `--space-*`, `--fs-*`, `--tap`, and the motion curves `--ease-out`/`--ease-in-out`. Size and space new UI from those tokens; a raw px value or a bare `ease`/`linear`/`ease-in` timing function in a rule is drift, not a choice. In both, `body` takes its colour from a variable that resolves once on `body`; descendants inherit the resulting colour, not the variable, so redefining a colour token on a subtree does nothing to inherited text unless that subtree also re-declares `color`. This bites any themed or inverted section (Design A's `.cta-module`, Design B's `.finale`).
- Motion follows one system per design, all in the page's own stylesheet + the shared `js/main.js`. `.reveal` marks a small, deliberate set of section-level blocks (never individual cards) for a one-time scroll entrance; it only ever hides content once `js/main.js` has confirmed `IntersectionObserver` support and no `prefers-reduced-motion`, at which point it adds `.js-reveal` to `<html>` and flips `.is-revealed` per element - without that ancestor class `.reveal` does nothing, so a failed script never leaves content stuck invisible. Both `@media print` blocks force `.reveal` fully visible regardless of scroll state, since the rider can be printed via keyboard shortcut before `#specs` has ever scrolled into view. Each design's hero has its own separate, simpler entrance (no JS, no scroll-triggering) since it's above the fold - Design A uses `@keyframes hero-reveal` staggered by `animation-delay`; Design B uses `.hero-line`/`.hero-media` `@keyframes` and, because those use `forwards` fill-mode, also needs an explicit `opacity: 1 !important; transform: none !important;` fallback in its reduced-motion block (`animation: none !important` alone would strip the end state). Reduced motion is handled once per stylesheet, globally: instead of zeroing every transition/animation duration (which would also kill colour/opacity fades), the block overrides `transition-property` to an allowlist of `color, background-color, border-color, opacity` and sets `animation: none`, so movement-bearing properties snap to their end state while colour and opacity keep fading. Any new pressable needs `transform: none !important` added to that block's explicit list alongside the press-feedback `scale(0.97)` it presumably declares on `:active`. The one mouse-reactive touch (3D tilt) is wired in `js/main.js` onto whatever element carries the `.hero-photo-frame` class - a wrapping div in Design A, the `<img>` itself in Design B - gated on `hover:hover`/`pointer:fine` and reduced motion together, and writes the perspective/rotate transform straight to `style.transform` (a deliberate choice over custom properties, to avoid triggering a style recalc on the subtree).
- The session-rate slider (`#hours-range`) is a custom-styled `<input type="range">` in both designs: `js/main.js` writes the fill percentage to `--range-fill` on the element itself (not a CSS class), and each stylesheet reads that variable in a `linear-gradient` on the track plus a `-moz-range-progress` fallback. Keep both in sync if you touch either.
- The gear-spec rows in `#specs` are captain-maintained: correct them to real equipment only on the captain's explicit instruction, and never invent, embellish, or guess a model, generation, or capability claim. Several legacy rows still describe gear the studio may not have; the captain corrects them incrementally, so raise a suspect row as a question rather than editing it unasked.
- `book@sonikbox.studio` is a placeholder inbox, not a live booking system. It's wired into the nav/hero/CTA-band buttons via `mailtoUrl()` in `js/main.js`, and separately hardcoded as a static `mailto:` href in each `.cta-address` fallback text link (hero, CTA band, footer) on both pages - update all of them if the address ever changes. A future task may need to swap this for a real backend/form.
- The `#specs` "Print Studio Rider" button (`js/main.js` `#print-rider-btn`) relies on the `@media print` rules at the bottom of each stylesheet, which hide everything except the gear-rider section and re-theme it black-on-white. The printed rider is its own document: it opens with the `.print-only` title block, hides the on-screen section head and any jump-nav, and drops to a single column with a wider label track. If you restructure `#specs` in either design, update that design's print rules too, and re-check that Module 05's two DJ add-on prices still print.
- `assets/img/control-room.jpg` and `assets/img/lounge.jpg` are the two real studio photos (downloaded from the live site, not placeholders) — shared by both designs for hero/hub imagery and as the Open Graph/Twitter preview image.
- No real logo asset exists in either design; the "SONIKBOX" wordmark is styled text, not an image/SVG mark.
