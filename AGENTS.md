# Project agent memory

This file is the project's committed home for project-intrinsic agent knowledge: build, test, release, architecture, and sharp-edge notes that should travel with the code.

- Static site, no build step: `index.html` + `css/styles.css` + `js/main.js`, no bundler/npm dependency. Open `index.html` directly or serve the directory; there is nothing to `npm install` or compile.
- Visual system is "Signal & Night" (shipped 2026-09, replacing the earlier "Rack Panel" orange-plate/screw-corner system - if you see references to `.rack-panel`, `.module-card`, `.hub-card`, `.summary-panel`, `.hero-photo-panel`, or Archivo Black elsewhere, they're stale). Two typefaces carry the whole page on purpose: Fraunces (display, headlines only) and IBM Plex Mono (everything else - body copy, labels, data, controls), both Google Fonts linked in `index.html`'s `<head>`. Warm near-black background, warm off-white ink, brand orange `#ff5500` as the one accent. Interactive controls (buttons, inputs, the hub toggle) keep sharp `border-radius: 0` corners; the page composition itself (hero, hubs, rider) is full-bleed and asymmetric rather than boxed cards.
- Orange is fill, never type - the one rule carried over from the old system, reimplemented as a handful of deliberate moments rather than a repeated plate: the `.hero-fill` highlighter behind the hero's second headline line, the `.logo-word .mark` nameplate chip ("BOX"), the small `.module-mark` patch-light square before each gear module heading, and the `.finale` section, which is the *only* place the whole page goes fully orange. Don't add more orange-fill moments without a reason; the restraint is the point.
- `css/styles.css`'s `:root` holds the whole design system: colour, `--space-*`, `--fs-*`, `--tap`, and the motion curves `--ease-out`/`--ease-in-out`. Size and space new UI from those tokens; a raw px value or a bare `ease`/`linear`/`ease-in` timing function in a rule is drift, not a choice. Breakpoints are 700px (label-track/two-column gear rows), 860px (nav switches from hamburger to inline links; hero, hubs, and the estimator switch to their two-column layouts), and 1200px (hero copy gets extra side padding on large desktop) - test states at 390/820 land below 860, 1024/1440 land above it.
- `body` takes its colour from `var(--ink-dim)`, which resolves once on `body`; descendants inherit the resulting colour, not the variable. Redefining a colour token on a subtree therefore does nothing to inherited text unless that subtree also re-declares `color`. This bites any themed or inverted section (see `.finale`, which re-declares colour throughout rather than relying on inheritance).
- Motion follows one system, all in `css/styles.css` + `js/main.js`. `.reveal` marks a small, deliberate set of section-level blocks (never individual cards) for a one-time scroll entrance; it only ever hides content once `js/main.js` has confirmed `IntersectionObserver` support and no `prefers-reduced-motion`, at which point it adds `.js-reveal` to `<html>` and flips `.is-revealed` per element - without that ancestor class `.reveal` does nothing, so a failed script never leaves content stuck invisible. The `@media print` block forces `.reveal` fully visible regardless of scroll state, since the rider can be printed via keyboard shortcut before `#specs` has ever scrolled into view. The hero's own entrance is separate (`.hero-line`/`.hero-media` `@keyframes`, staggered by `animation-delay`, no JS, no scroll-triggering) since it's above the fold; because those animations use `forwards` fill-mode, the reduced-motion block's `animation: none !important` alone would strip the end state, so `.hero-line`/`.hero-media` also get an explicit `opacity: 1 !important; transform: none !important;` fallback there. Reduced motion is handled once, globally: instead of zeroing every transition/animation duration (which would also kill colour/opacity fades), the block overrides `transition-property` to an allowlist of `color, background-color, border-color, opacity` and sets `animation: none`, so movement-bearing properties snap to their end state while colour and opacity keep fading. Any new pressable needs `transform: none !important` added to that block's explicit list alongside the press-feedback `scale(0.97)` it presumably declares on `:active`. The one mouse-reactive touch (3D tilt) is wired in `js/main.js` onto whatever element carries the `.hero-photo-frame` class - that's the `<img>` itself now, not a wrapping panel div - gated on `hover:hover`/`pointer:fine` and reduced motion together, and writes the perspective/rotate transform straight to `style.transform` (a deliberate choice over custom properties, to avoid triggering a style recalc on the subtree).
- The session-rate slider (`#hours-range`) is a custom-styled `<input type="range">`: `js/main.js` writes the fill percentage to `--range-fill` on the element itself (not a CSS class), and `css/styles.css` reads that variable in a `linear-gradient` on the track plus the `-moz-range-progress` fallback. Keep both in sync if you touch either.
- The gear-spec rows in `#specs` are captain-maintained: correct them to real equipment only on the captain's explicit instruction, and never invent, embellish, or guess a model, generation, or capability claim. Several legacy rows still describe gear the studio may not have; the captain corrects them incrementally, so raise a suspect row as a question rather than editing it unasked.
- `book@sonikbox.studio` is a placeholder inbox, not a live booking system. It's wired into the nav/hero/CTA-band buttons via `mailtoUrl()` in `js/main.js`, and separately hardcoded as a static `mailto:` href in each `.cta-address` fallback text link (hero, CTA band, footer) - update both if the address ever changes. A future task may need to swap this for a real backend/form.
- The `#specs` "Print Studio Rider" button (`js/main.js` `#print-rider-btn`) relies on the `@media print` rules at the bottom of `css/styles.css`, which hide everything except `.rider` (`#specs`) and re-theme it black-on-white. The printed rider is its own document: it opens with the `.print-only` title block, hides the on-screen `.rider-head` and the `.rider-index` jump-nav, and flattens `.rider-body` plus every `.module-row-stacked` (Module 05's synth/drum/DJ rows) to a single column so a long label and its tag never fight for a narrow track. If you restructure `#specs`, update those print rules too, and re-check that Module 05's two DJ add-on prices still print.
- `assets/img/control-room.jpg` and `assets/img/lounge.jpg` are the two real studio photos (downloaded from the live site, not placeholders) — reused for hero/hub imagery and as the Open Graph/Twitter preview image.
- No real logo asset exists; the "SONIKBOX" wordmark is styled text (`.logo-word` in `css/styles.css`, with "BOX" set as an orange fill chip), not an image/SVG mark.
